# SEO Implementation — zubyr.dev (retrofit into existing project)

Scope: **SEO and AI-readability only.** No redesign, no rebuild. This is the extracted SEO layer from the portfolio blueprint, rewritten as a retrofit plan for the existing Next.js App Router site.

Goal: rank #1 for "Zubair Bin Shaukat" / "zubyr dev", earn Google sitelinks, and be the source AI tools quote from instead of LinkedIn.

---

## 0. The one governing rule

> **Every word Google or an AI needs must exist in server-rendered HTML before any JavaScript runs.**

Animation and 3D are decoration layered on top of real, crawlable text — never a container for it. Test: if you delete the canvas and disable JS, the site must still be a complete, readable, rankable website.

Practical checks in the existing project:
- View source (`Ctrl+U`) on every page — if you can't find your headings and body copy in the raw HTML, that page is invisible to crawlers.
- No copy inside a `<canvas>`, no copy that only mounts after a loader/scroll trigger.
- Keep components as **Server Components** by default; `"use client"` only on canvas, animated wrappers, and interactive islands.
- Navigation must be real crawlable `<a>` / `next/link` tags — not JS-only scroll handlers.

## 1. Site architecture (the thing that earns sitelinks)

Sitelinks are **generated by Google from your page hierarchy + internal links**. They cannot be requested via code. A single long-scroll page will never get them. You need real routes.

> Note: the mini search box that used to appear inside sitelinks was removed by Google in **Nov 2024** — do **not** build `SearchAction` schema, it does nothing now.

### Route map

| Route | Title tag (short — Google uses it as the sitelink label) | H1 | Primary keyword |
|---|---|---|---|
| `/` | Zubair Bin Shaukat — Software Engineer & Problem Solver | Zubair Bin Shaukat | zubair bin shaukat, zubyr dev |
| `/about` | About — Zubair Bin Shaukat | About Zubair Bin Shaukat | who is zubair bin shaukat |

| `/projects/[slug]` | {Project} — Case Study | {Project name} | project-specific |
| `/blog` | Blog — Zubair Bin Shaukat | Engineering Notes | — |
| `/blog/[slug]` | {Post title} | {Post title} | post-specific |

Rules:
- **One `<h1>` per page**, then logical `h2` / `h3`. Real `<nav>`, `<main>`, `<article>`, `<footer>` landmarks.
- Homepage links to **all** top-level pages in both nav and footer — that's the internal-link signal sitelinks are picked from.
- Each service page links back to `/` and cross-links to the other services.
- **Meta description: 150–160 chars, unique per page.** Write it like the grey line under a Google sitelink: one factual sentence + one benefit.

### Migration note
If pages currently exist as sections on one page (`/#services`), create the real routes and keep the homepage sections as *summaries that link* to them. Set up **301 redirects** from any old URL (including `*.vercel.app`) to the new `zubyr.dev` path in `next.config.js`.

## 3. Structured data (JSON-LD) — the highest-leverage item

One `<script type="application/ld+json">` on the homepage, rendered from a **server component**. This is what merges "your LinkedIn + your GitHub + your site" into a single entity in Google's Knowledge Graph, and gives AI a clean fact sheet.

### Per-page schema

| Page type | Schema | Key fields |
|---|---|---|
| `/services/*` | `Service` | `provider: { "@id": ".../#person" }`, `serviceType`, `areaServed` |
| `/projects/[slug]` | `CreativeWork` (or `Article`) | `author: { "@id": ".../#person" }`, `datePublished` |
| `/blog/[slug]` | `Article` | `author @id`, `datePublished`, `dateModified`, `headline`, `image` |
| Homepage FAQ block | `FAQPage` | must match the **visible** on-page Q&A word for word |
| All inner pages | `BreadcrumbList` | reinforces hierarchy → helps sitelinks |

Validate every page at Google's Rich Results Test and Schema.org validator before shipping.

## 4. Crawl infrastructure

### `app/sitemap.ts`

```ts
import type { MetadataRoute } from "next";

const base = "https://www.zubyr.dev";

export default function sitemap(): MetadataRoute.Sitemap {
  const routes = ["", "/about", "/services/gohighlevel", "/services/automation",
    "/services/web-development", "/services/mobile", "/projects", "/blog", "/contact"];

  return routes.map((r) => ({
    url: `${base}${r}`,
    lastModified: new Date(),
    changeFrequency: r === "" ? "weekly" : "monthly",
    priority: r === "" ? 1 : 0.8,
  }));
  // append projects + blog posts mapped from your MDX index
}
```

### `app/robots.ts` — explicitly allow AI crawlers

```ts
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      { userAgent: "*", allow: "/" },
      { userAgent: ["GPTBot", "ClaudeBot", "PerplexityBot", "Google-Extended",
                    "OAI-SearchBot", "Applebot-Extended"], allow: "/" },
    ],
    sitemap: "https://www.zubyr.dev/sitemap.xml",
    host: "https://www.zubyr.dev",
  };
}
```

You **want** to be ingested. Do not block these.

### Search Console — day one
- Verify the domain, submit `sitemap.xml`.
- Request indexing for each new route once.
- Watch the Core Web Vitals report — that's the score Google actually uses, not your local Lighthouse run.
- Also verify in **Bing Webmaster Tools** (ChatGPT search leans on Bing's index).

## 5. AI-readability layer

What makes ChatGPT / Claude / Perplexity / Google AI Mode describe you **from your site** instead of guessing from LinkedIn:

1. **Server-rendered semantic HTML** — the #1 factor by a wide margin. See rule 0.
2. **`/about` written in the third person, fact-dense.** The first two sentences must fully answer "Who is Zubair Bin Shaukat?" — name, role, location, specialties. Then: stack, years, notable outcomes, links. AI quotes facts, not vibes.
3. **FAQ block with literal question headings** on the homepage (and mirrored in `FAQPage` schema):
   - `<h3>Who is Zubair Bin Shaukat?</h3>`
   - `<h3>What services does Zubair Bin Shaukat offer?</h3>`
   - `<h3>Where is Zubair Bin Shaukat based?</h3>`
   - `<h3>How can I hire Zubair Bin Shaukat?</h3>`
   Answers in plain, complete, factual sentences — AI systems lift these close to verbatim.
4. **Consistent naming.** "Zubair Bin Shaukat" spelled identically everywhere: site, schema, LinkedIn, GitHub, OG tags. Inconsistency splits the entity.
5. **`/llms.txt`** at root — a markdown list of your key pages with one-line descriptions. Honest assessment: **low value today** (adoption is ~10% of domains, and Google has confirmed Search ignores it, though some AI tools do fetch it). 20 minutes, zero risk. Ship it, don't count on it.
6. **Descriptive `alt` text** on every image — images are also an AI signal, and alt text is a Lighthouse accessibility requirement.

## 8. Performance rules that protect SEO

Only the constraints that affect ranking — Core Web Vitals are a live ranking signal and 3D is the usual thing that breaks them.

- **LCP must be an HTML element** (the hero heading), never the canvas. Target < 2.5s.
- **CLS = 0** — explicit `width`/`height` on all images, reserved space for the canvas.
- Three.js in its own lazy chunk: `dynamic(() => import(...), { ssr: false })`, loaded after first paint. Initial route JS < 120KB gzip.
- Any preloader is a **cosmetic overlay on already-painted HTML**, never a gate in front of it. Verification: Lighthouse score must be identical with it on and off.
- `next/image`, AVIF/WebP, `priority` only on the single above-fold image.
- Max 2 font families + 1 mono, variable, subset, `display: swap`, preloaded.
- No third-party scripts on v1 except analytics. No chat widgets, no GTM.
- Accessibility is 25% of Lighthouse **and** an AI-parsing signal: contrast ≥ 4.5:1, focus-visible styles, aria-labels on icon buttons, skip-to-content link, `aria-hidden="true"` on the canvas.
- `prefers-reduced-motion: reduce` → kill smooth scroll and canvas autoplay.

## 9. Retrofit order

Do it in this sequence — each step is worthless without the one before it.

1. **Audit** — view-source every existing page. List what's missing from the raw HTML. Fix that first.
2. **Routes** — split the single page into the real route map (§1). 301 old URLs.
3. **Metadata** — layout defaults + per-page title/description/canonical (§2).
4. **Schema** — homepage `@graph`, then per-page types (§3). Validate.
5. **Crawl infra** — sitemap, robots, Search Console, Bing (§4).
6. **Content** — rewrite `/about` fact-dense third person, add the FAQ block (§5).
7. **Off-site** — the entity checklist, all in one sitting (§6).
8. **Perf pass** — Lighthouse mobile preset on `/`, one service page, one project page (§8).
9. **Blog** — start shipping posts (§7).
